결과 채널을 먼저 구독한 뒤 분산 락을 획득한 요청 하나만 Stream에 작업을 넣습니다. 나머지 동시 요청은 같은 결과를 기다립니다.

처리 순서

성공 결과의 DB 저장 책임은 AI worker가 아니라 FastAPI에 있습니다.

01

요청 검증

진료기록과 최신 X-Ray를 조회하고 모델 키를 검증합니다.

02

DB 캐시 확인

동일 이미지·모델의 유효한 분석 결과가 있으면 즉시 반환합니다.

03

결과 채널 구독

빠른 작업 결과를 놓치지 않도록 큐 등록보다 Pub/Sub 구독을 먼저 수행합니다.

04

락 + XADD

SET NX EX로 중복 작업을 막고 prediction:tasks에 이벤트를 추가합니다.

05

XREADGROUP

여러 worker 중 하나가 consumer group을 통해 작업을 원자적으로 받습니다.

06

모델 추론

공유 media 볼륨의 X-Ray를 읽고 폐렴 판정, Confidence, Heatmap을 생성합니다.

07

Publish + ACK

결과를 임시 캐시와 채널에 발행한 뒤 작업을 XACK하고 Stream에서 제거합니다.

08

저장 + 응답

FastAPI가 결과를 MySQL에 저장하고 락을 해제한 후 API 응답을 반환합니다.

Failure Strategy

비정상 종료에도 작업 보존

  • worker는 결과 발행 전까지 작업을 ACK하지 않습니다.
  • 종료된 consumer의 pending 작업은 일정 idle 시간 후 XAUTOCLAIM됩니다.
  • 다른 worker가 claim한 작업을 다시 추론하고 결과를 발행합니다.
  • DB 유니크 키가 최종 중복 저장을 한 번 더 방지합니다.
